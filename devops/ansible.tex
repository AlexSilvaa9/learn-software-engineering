\section{Qué es Ansible y por qué importa}

Ansible es una plataforma de automatización \textbf{agentless} orientada a configuración, despliegue, orquestación y operación repetible.

\subsection{Problemas que resuelve}
\begin{itemize}
  \item Eliminación de tareas manuales repetitivas e inconsistentes.
  \item Estandarización de configuración entre entornos.
  \item Reducción de drift operacional y errores humanos.
  \item Trazabilidad de cambios vía Git + pipelines.
\end{itemize}

\subsection{Conceptos base}
\begin{itemize}
  \item \textbf{Inventory}: hosts y grupos objetivo.
  \item \textbf{Playbook}: automatización declarativa en YAML.
  \item \textbf{Task}: unidad mínima de acción.
  \item \textbf{Role}: empaquetado reusable de automatización.
  \item \textbf{Collection}: distribución modular de plugins/módulos.
  \item \textbf{Vault}: cifrado de secretos.
\end{itemize}

\section{Ansible en on-premise, cloud e híbrido}

Sí, Ansible funciona perfectamente en \textbf{on-premise}. De hecho, es uno de sus casos más fuertes.

\subsection{Targets típicos}
\begin{itemize}
  \item Linux (Ubuntu, RHEL, Debian, Rocky, etc.).
  \item Windows Server (WinRM).
  \item Equipos de red (Cisco, Juniper, Arista, Fortinet, Palo Alto).
  \item Virtualización (VMware), cloud pública y Kubernetes.
\end{itemize}

\subsection{Patrón híbrido recomendado}
\begin{enumerate}
  \item Terraform aprovisiona infraestructura base.
  \item Ansible configura sistemas y operación day-2.
  \item GitOps gestiona aplicaciones en Kubernetes.
\end{enumerate}

\section{Playbooks y idempotencia profesional}

\subsection{Playbook base}
\begin{lstlisting}[caption=Instalación y servicio]
- name: Configurar web servers
  hosts: web
  become: true
  tasks:
    - name: Instalar nginx
      ansible.builtin.apt:
        name: nginx
        state: present
        update_cache: true

    - name: Habilitar servicio nginx
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true
\end{lstlisting}

\subsection{Idempotencia real}
\begin{itemize}
  \item Prefiere módulos declarativos sobre \texttt{shell}/\texttt{command}.
  \item Define estados explícitos (\texttt{present}, \texttt{absent}, \texttt{started}).
  \item Evita tareas no deterministas.
\end{itemize}

\section{Variables, precedence y modelado limpio}

\subsection{Fuentes comunes de variables}
\begin{itemize}
  \item \texttt{defaults/main.yml} (role defaults).
  \item \texttt{group\_vars}/\texttt{host\_vars}.
  \item Variables en playbook/role.
  \item Extra vars (\texttt{-e}) con prioridad alta.
\end{itemize}

\subsection{Reglas prácticas}
\begin{enumerate}
  \item Valores por defecto en \texttt{defaults}.
  \item Valores por entorno en \texttt{group\_vars}.
  \item Nunca esconder lógica crítica solo en \texttt{-e}.
\end{enumerate}

\section{Templates, handlers y control de cambios}

\begin{lstlisting}[caption=Template + notify handler]
- name: Render nginx config
  ansible.builtin.template:
    src: nginx.conf.j2
    dest: /etc/nginx/nginx.conf
    mode: '0644'
  notify: restart nginx

handlers:
  - name: restart nginx
    ansible.builtin.service:
      name: nginx
      state: restarted
\end{lstlisting}

\subsection{Buenas prácticas}
\begin{itemize}
  \item Cambios config siempre con \texttt{notify}.
  \item Handlers idempotentes y específicos.
  \item Plantillas versionadas y testeadas.
\end{itemize}

\section{Control de flujo avanzado}

\subsection{when, loop, tags, include/import}
\begin{lstlisting}[caption=Flujo avanzado]
- name: Instalar paquetes base
  ansible.builtin.apt:
    name: "{{ item }}"
    state: present
  loop:
    - curl
    - git
    - jq
  tags: [base, packages]

- name: Ejecutar sólo en Debian
  ansible.builtin.service:
    name: cron
    state: restarted
  when: ansible_facts['os_family'] == 'Debian'
\end{lstlisting}

\subsection{Manejo robusto de errores}
\begin{lstlisting}[caption=block/rescue/always]
- name: Cambio crítico con rollback
  block:
    - name: Aplicar cambio
      ansible.builtin.command: /usr/local/bin/apply_change

  rescue:
    - name: Ejecutar rollback
      ansible.builtin.command: /usr/local/bin/rollback_change

  always:
    - name: Registrar estado
      ansible.builtin.debug:
        msg: "Cambio finalizado"
\end{lstlisting}

\section{Kubernetes con Ansible (EKS/AKS/GKE/on-prem)}

\subsection{Módulos y enfoque recomendado}
\begin{itemize}
  \item Colección \texttt{kubernetes.core} para recursos K8s.
  \item Helm vía módulos o CLI controlada.
  \item Ansible para bootstrap y operación; GitOps para apps de alto churn.
\end{itemize}

\begin{lstlisting}[caption=Namespace + deployment simple]
- name: Operación sobre k8s
  hosts: localhost
  gather_facts: false
  tasks:
    - name: Crear namespace
      kubernetes.core.k8s:
        state: present
        definition:
          apiVersion: v1
          kind: Namespace
          metadata:
            name: plataforma
\end{lstlisting}

\subsection{Patrón Terraform + Ansible + GitOps}
\begin{enumerate}
  \item Terraform crea clúster y red base.
  \item Ansible instala add-ons operativos (monitoring/logging/seguridad).
  \item GitOps gestiona aplicaciones y releases continuas.
\end{enumerate}

\section{Rendimiento y estrategia de ejecución}

\subsection{Parámetros clave}
\begin{itemize}
  \item \texttt{forks}: paralelismo.
  \item \texttt{serial}: rolling updates.
  \item \texttt{strategy}: \texttt{linear} / \texttt{free}.
  \item \texttt{throttle}: limitar concurrencia en tareas sensibles.
\end{itemize}

\begin{lstlisting}[caption=Rolling update seguro]
- name: Deploy por lotes
  hosts: web
  serial: 2
  become: true
  tasks:
    - name: Actualizar app
      ansible.builtin.apt:
        name: myapp
        state: latest
\end{lstlisting}

\section{AWX / Ansible Automation Platform}

\subsection{Qué aporta a escala}
\begin{itemize}
  \item RBAC, auditoría y ejecución centralizada.
  \item Job templates, schedules, credenciales seguras.

\begin{enumerate}

\section{Seguridad y compliance}

\begin{itemize}
  \item Principio de mínimo privilegio (SSH/WinRM/sudo).
  \item Secretos solo por Vault o gestor externo.
  \item Inventarios, playbooks y cambios siempre auditables.
  \item Hardening automatizado (benchmarks CIS) y verificación continua.
\end{itemize}

\section{Migración desde scripts legacy a Ansible}

\subsection{Plan de migración por fases}
\begin{enumerate}
  \item Inventariar scripts críticos y dependencias.
  \item Convertir tareas comunes a roles reutilizables.
  \item Añadir tests y validación en CI.
  \item Decomisionar scripts antiguos por etapas.
\end{enumerate}

\subsection{Matriz de riesgo}
\begin{longtable}{p{0.30\textwidth} p{0.18\textwidth} p{0.42\textwidth}}
\toprule
\textbf{Tipo de cambio} & \textbf{Riesgo} & \textbf{Mitigación} \\
\midrule
Cambios de red/firewall & Alto & Ventana controlada, validación previa, rollback probado. \\
Parches SO en masa & Medio-Alto & \texttt{serial}, canary y monitoreo post-cambio. \\
Deploy de app stateless & Medio & Blue/green o rolling con health checks. \\
Hardening baseline & Medio & Entorno piloto + escaneo de cumplimiento. \\
\bottomrule
\end{longtable}

\section{Anti-patrones que debes evitar}

\begin{enumerate}
  \item Playbooks monolíticos gigantes sin roles.
  \item Uso excesivo de \texttt{shell}/\texttt{command} para todo.
  \item Variables opacas y sin convención de nombres.
  \item Secretos en texto plano en repositorio.
  \item Ejecutar en producción sin \texttt{--check} previo en entorno similar.
\end{enumerate}

\section{Troubleshooting experto}

\subsection{Errores comunes y solución}
\begin{longtable}{p{0.34\textwidth} p{0.56\textwidth}}
\toprule
\textbf{Problema} & \textbf{Acción recomendada} \\
\midrule
UNREACHABLE por SSH & Revisar red, usuario, llaves, firewall, \texttt{ansible\_host}. \\
Cambios en cada ejecución & Revisar idempotencia y módulos no declarativos. \\
Error de permisos sudo & Validar \texttt{become}, \texttt{become\_user} y sudoers. \\
Variables no aplican & Revisar precedencia y colisiones \texttt{group\_vars}/\texttt{host\_vars}. \\
Timeouts frecuentes & Ajustar forks/serial/timeout y dividir tareas pesadas. \\
\bottomrule
\end{longtable}

\texttt{Role} & Componente reusable con tareas, vars y handlers. \\
\texttt{Collection} & Paquete de contenido Ansible (módulos/plugins/roles). \\
\texttt{Vault} & Cifrado de secretos para uso seguro en playbooks. \\
\texttt{Idempotencia} & Ejecutar múltiples veces sin producir drift no deseado. \\
\texttt{Handler} & Tarea disparada por \texttt{notify}, normalmente para reinicios. \\
\texttt{AWX/AAP} & Plataforma de ejecución centralizada y gobernada de Ansible. \\
\bottomrule
\end{longtable}

\section{Conclusión}

Ansible alcanza su nivel \textit{master} cuando se combina:
\begin{itemize}
  \item diseño limpio de roles y variables,
  \item seguridad de secretos y acceso,
  \item pruebas y automatización CI/CD,
  \item y operación con trazabilidad en producción.
\end{itemize}

Si aplicas este contenido con laboratorios y revisión técnica en equipo, tendrás dominio profesional de Ansible para entornos reales.
